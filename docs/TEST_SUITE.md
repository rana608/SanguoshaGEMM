# 三国杀 GEMM：多测试集极速对比

此文档描述扩容前的历史 96 例测试，报告中的程序哈希对应保留的旧版。历史 0–100 扩容测试见 `evidence/expanded/suite-v1/report.html`；当前统一牌堆规则与验收见 `docs/UNIFORM_DECK.md`。

这份测试包提供 **96 组不同的 A、B 输入**，用于比较两个独立 Windows 程序。输入在计时前生成并固定，不按测量后的快慢挑选。该轮测试的计算范围是各维度 1–2、整数 0–9。

## 测试集组成

| 分组 | 输入数 | 分布 |
| --- | ---: | --- |
| 稠密低值 | 11 | A、B 均为 1–3 |
| 稠密均匀 | 11 | A、B 均为 1–9 |
| 稠密高值 | 11 | A、B 均为 7–9 |
| 左大右小 | 11 | A 为 7–9，B 为 1–3 |

| 固定边界与回归 | 8 | 左零、右零、双方零、双方全 9、稠密相等循环次数、右矩阵整行/列零、指定样例 |

覆盖 m、k、n 分别取 1 或 2 的全部 8 种尺寸组合，其中 40 组为完整 2×2 乘法。55 组来自两边均无零的稠密分布。没有额外加入之前用于演示的 2×2 单位矩阵性能样例。

输入种子为 `20261103`，测试顺序种子为 `20261104`。生成器在运行前对 A/B 精确去重；本版本 96 个候选均不同。清单位于 `examples/suites/sgemm-v1/catalog.json`，每组还有独立 JSON 文件。稀疏度是生成概率，不保证小矩阵恰好有指定比例的零；实际比例逐例记录。

## 查看结果

打开 `evidence/versions/suite-v1/report.html`。它显示：

- 按分布和尺寸分组的全部结果，以及快、接近、慢的数量。
- 每组实际 A、B、C，两个程序的用时和出杀次数。
- 引擎结算、准备＋结算、包含程序启动的总用时，分别显示。
- 单例详细报告、每次原始记录、JSON 和 CSV 汇总。
- 按类别、快慢或矩阵数字筛选，包含没有收益和变慢的用例。

便携程序包附带的 `test-suite-report/report.html` 是同一次实测的浏览版；轻量测试集 ZIP 和源码包保留完整原始记录。

本机已完成全部 2,112 次调用，96 组结果全部正确；按准备＋结算耗时分档为 48 组更快、46 组接近、2 组更慢。实测分析见 `docs/TEST_SUITE_RESULTS.md`（源码工作区中也可从本文件同目录打开）。

## 运行方法

在完整源码工作区中运行全套：

```powershell
python scripts/benchmark.py --runs 10
```

每次默认创建新的报告目录。指定输出目录：

```powershell
python scripts/benchmark_suite.py --runs 10 --output-dir suite-results/my-run
```

仅持有测试集 ZIP 时，解压后在其目录运行，并指定两个程序路径：

```powershell
python scripts/benchmark_suite.py --runs 10 --baseline ../SanguoshaGEMM-Baseline/SanguoshaGEMM-Baseline.exe --optimized ../SanguoshaGEMM-Optimized/SanguoshaGEMM-Optimized.exe
```

需要 Python 3.11+。原生程序包的根目录也附带 `benchmark_suite.py` 与输入，两个程序包并排解压后可执行 `python benchmark_suite.py --runs 10`。

每例每版先预热 1 次，再实测 10 次；版本先后顺序逐轮交替，串行执行。96 例合计 **2,112 次原生进程调用**。这是完整实测，耗时会明显长于单一演示样例。全部在后台进行，不操作桌面。进度与失败会即时写入报告；中途失败的用例不会被隐藏。

每次调用均读取游戏引擎结果，并用独立整数乘法核验。同一输入下两版必须给出相同 C。输入哈希、程序哈希及测量脚本哈希均记录在汇总中。

无需再次计时即可审计随包原始记录：`python scripts/verify_suite.py`。完整续跑可在原命令后加 `--resume`；输入、程序、运行次数或测量脚本变化时会拒绝合并。`evidence/versions/suite-v1/method/` 保留当时实际使用的测量脚本，便于核对方法哈希。

## 计时解释

`engineMs` 是实际出牌结算时间。`computeMs = prepareMs + runWallMs` 是程序报告的局面初始化与结算阶段时间。输入解析、任务编排、部分房间建立、结果写出等开销都包含在外部测量的 `processWallMs` 中。三个口径分别展示，避免把启动成本混入引擎结算。

分组比较采用各用例 `computeMs` 中位数之比，大于 1 表示优化版较快。±5% 标为“接近”，只是展示区间，不是统计显著性结论。零结算时间的引擎倍数标记为不适用，不当作 1× 或无限倍。p95 使用 nearest-rank；10 个样本时等于最大值。

这是当前小矩阵范围的合成测试集，不代表任意输入分布、大矩阵 GEMM、BLAS 或 GPU 性能。原始单位矩阵演示的倍数不能用作一般性能结论。需要看分组结果和完整逐例表。
