# 96 组矩阵的双版本实测结果

2026-11-03，本机 Windows，Qt 5.5.1 / MinGW 4.9.2，原始版与优化版均为 Release、极速模式（speed=2），后台运行。两个原生可执行文件与之前交付版本一致，本轮没有根据结果调整算法或删选输入。

**96 组唯一输入、2,112 次程序调用，结果全部正确。** 每例每版先预热 1 次、测量 10 次，串行执行并逐轮交替版本顺序。输入和类别在计时前固定，生成与执行顺序分别使用种子 20261103、20261104。包含 8 种尺寸、40 组完整 2×2 乘法，55 组来自双方均无零的稠密分布。

完整可筛选报告：`evidence/versions/suite-v1/report.html`；实际矩阵和数字表：同目录 `summary.csv`；每次原生动作记录：`cases/case-NNN/`。

## 计时、核验与复现

- `engineMs`：实际出牌的引擎结算，排除准备、主动等待、启动和渲染。
- `computeMs = prepareMs + runWallMs`：程序报告的局面准备和结算阶段。输入解析、任务编排、部分房间建立和结果输出不在此范围。
- `processWallMs`：外部测量的整个程序调用，包含上述开销及程序启动。三种口径逐例并列。

每次调用均与独立整数乘法比较。额外审计全部原生记录中的结果手牌、曹丕最终与逐步救援后 1 血、实际摸牌数量、汇总中位数和输入哈希。`integrity.json` 保存审计结果。`method/` 保存本次实测使用的两份测量脚本，拼接 SHA256 与主汇总相符；后续工具修复了完整报告续跑，并加入自动保存测量脚本，未修改本次测量数据。
