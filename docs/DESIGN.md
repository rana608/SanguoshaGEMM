# 三国杀 GEMM

已批准设计：使用 QSanguosha-v2 原生 C++/Qt 客户端，增加独立 gemm 场景。张飞的普通杀使 1 血曹丕濒死；华佗急救；曹丕恢复到 1 血，原版放逐令结果角色摸 maxhp-1 张。重复 A[i,k] 次，B[k,j] 编码为曹丕 maxhp-1。所有运算处于同一出牌阶段。

最多 2+k*n+m*n 名角色。张飞装备麒麟弓，华佗预置 72 张红牌，扩展摸牌堆固定为 1024 张。结果角色起始零牌。输入编译只产生出牌任务，不计算乘积。结果仅读取手牌数量。

baseline-v1：i,j,k 串行，不跳过 B=0。sparse-v1.1：跳过零项。transpose-v1.2：比较两个方向的任务数量，采用更短者，结果映射回原坐标。万箭齐发批处理为后续实验，未经实测不宣称优化。

界面复用原版 RoomScene/Photo/Dashboard/CardItem。增加矩阵入口与控制条；正常、加速、极速模式。极速执行相同引擎规则，关闭人为等待和装饰动画。记录含输入、版本、初始局面、每步实际结果和统计。

交付：Windows 便携程序、源码、构建脚本、验证报告。上游许可证和原素材保持原样。测试与验收证据保存在 evidence/，当前状态只写 NEXT.md。

当前发行要求：两个分别链接的程序包。Baseline 仅接受 baseline-v1，Optimized 仅接受 transpose-v1.2。配置固定到各自可执行文件目录、默认记录按版本和时间戳区分，本地牌桌使用系统分配端口。中间 sparse-v1.1 仅留作历史实验资料。共享原版引擎源码，各版算法不能由运行时配置互相切换。
